# `tests/core/test_resources.py`

> Tests that `gif_editor.resources` finds the bundled icons from the source tree and from a onefile build's unpack folder, and never raises (M5).

## Where it sits
- **Layer:** tests (core, no Qt)
- **Used by:** pytest.
- **Uses:** `gif_editor/resources/__init__.py` (`icon_path`, `resource_path`), the committed files in `src/gif_editor/resources/icons/`, pytest's `monkeypatch` and `tmp_path`.

## Public API
| Test | Verifies |
|---|---|
| `test_resource_path_finds_the_icons` | `resource_path("icons")` is a folder and contains `icon.ico`. **This is the test that exposed the `resources/resources` bug.** |
| `test_icon_path_prefers_the_platform_format` | With `sys.platform` patched to `win32` the icon is the `.ico`; with `linux` it is the `.png`. |
| `test_icon_path_returns_none_when_nothing_is_bundled` | With `resource_path` patched to a nonexistent path, `icon_path()` is `None` (no exception). |
| `test_resource_path_uses_the_onefile_env_var` | A fake unpack folder `tmp/gif_editor/resources/icons/icon.ico` with `NUITKA_ONEFILE_DIR=tmp`, and the module's `__file__` pointed elsewhere: `resource_path` returns the file from the env-var root. |
| `test_missing_resource_returns_the_expected_path` | A missing name returns a path ending in that name that does not exist, instead of raising. |

**5 test cases.**

## How it works
Plain function calls with `monkeypatch`. The onefile case imitates Nuitka's layout instead of building: it creates the folder structure Nuitka unpacks to and sets the variable Nuitka sets. Patching `__file__` makes the source-tree root miss, so only the environment-variable route can find the file.

## Invariants & gotchas
- Depends on the committed icon files existing (they are generated by `scripts/make_icon.py` and checked by `--check` in CI).
- `monkeypatch` restores `sys.platform`, `__file__` and the environment after each test.

## Tests
- **Gaps:** that `app.main` really sets the window icon is not asserted by a test (it was checked by hand after the fix); a real onefile layout is only exercised by running a build.
